## 1. 진입과 화면 흐름

- 첫 진입은 **개인 / 멀티 선택 화면**. `/?room=CODE` 링크는 선택 화면을 건너뛰고 바로 그 방으로 간다.
- 새 라우트를 만들지 않는다. `/` 안의 화면 상태로 둔다 (프리렌더 셸 유지).

```
선택 → 로비(공개 방 목록 · 방 만들기 · 코드 입력) → 대기실 → 게임 → 결과
      → 방장이 다음 게임 선택 → 대기실(전원 준비 해제) → …
```

### 멀티 게임 화면

| 항목 | 내용 |
|---|---|
| 배치 | 가운데에 개인 플레이와 같은 보드·키보드. 상대 패널은 **좌·우 여백에 2개씩 세로로**(□나□ / □나□), 위·아래에는 두지 않는다 (2026-11-01 캔버스 댓글로 결정) |
| 모바일 | 여백이 없으므로 패널을 **보드 위 가로 띠**로 내린다 (넘치면 가로 스크롤) |
| 패널 내용 | 이름, 상태(제안함 / 풀이 중 / 완료 n위 / 탈락 / 접속 끊김) |
| 협동 패널 | 그 사람이 제안 중인 단어 (실시간) |
| 경쟁 패널 | 같은 격자에서 제출한 행의 **색만** (자모 숨김). 입력 중인 행은 비움 |

### 채팅 없음, 재촉

- v1에는 채팅이 없다.
- 대기실에 **"재촉" 버튼**: 방장 화면 전체 알림 레이어(소리·흔들림·배지, 닫을 때까지 유지), 1인당 30초 쿨다운. 2026-11-01 결정. 언제나 가능한 "나가기".
- 방장 잠수는 시스템이 풀지 않는다 (자동 방장 교체·자동 시작 없음). 사용자 결정: 보통 독촉하다 안 되면 방을 나가 다른 방을 찾는다.

## 2. 방 규칙

| 항목 | 규칙 | 구분 |
|---|---|---|
| 방 코드 | 6자, 대문자+숫자, 혼동 문자 `0 O 1 I` 제외 | 기본값(제안) |
| 노출 | 공개 목록에 노출, 링크로도 입장 | 사용자 결정 |
| 인원 | 2~5 (협동·경쟁 동일). 방장 혼자 시작 불가 | 사용자 결정 |
| 계정 | 없음. 닉네임만 | 전제(AGENTS.md: 사용자 계정 없음) |
| 닉네임 충돌 | 서버가 접미사를 붙이고 확정 이름을 입장 응답에 넣는다 | 기본값(제안) |
| 방장 승계 | 방장이 **실제로 나가거나 끊기면** 입장 순으로 접속 중인 다음 사람. 끊김은 5초 유예 | 5초: 기본값(제안) |
| 빈 방 소멸 | 전원이 '나가기'로 떠나면 즉시. 끊김이 섞여 접속자가 0이 되면 30초 유예 뒤 (2026-11-05 2분에서 변경) | 기본값(제안) |
| 목록 노출 | 접속자가 있는 방만. Room이 접속자가 있는 동안 60초마다 Lobby에 다시 알리고(심장박동), Lobby는 150초 안에 알림이 온 방만 낸다. DO가 재시작되면 저장된 접속 상태를 믿지 않고 열린 소켓과 대조(reconcile)해 정리한다 | 기본값(제안) |

### localStorage 새 키

| 저장소 | 키 | 값 |
|---|---|---|
| localStorage | `nkordle:mp-session` | 임시 계정 `{ token, name, exp }` (이것 하나뿐, 2026-11-01 사용자 결정) |

sessionStorage·BroadcastChannel·쿠키는 쓰지 않는다. 새로고침·재접속·같은 브라우저의 새 탭은 토큰의 같은 `uid`로 같은 자리에 복귀한다(끊김 60초 규칙은 그대로). 기존 키 형식은 건드리지 않는다. 자세한 원칙은 §7 "브라우저 저장 최소화와 임시 계정".

### 준비

- **방장을 뺀 전원이 준비 완료여야 시작 버튼이 켜진다.** 방장 화면에 인원별 준비 상태와 "n명 대기 중".
- 방장이 **규칙에 영향 주는 설정**을 바꾸면 전원 준비 해제.
- 게임이 끝나 다음 게임을 고를 때도 전원 준비 해제 후 같은 절차.
- 접속 끊긴 사람은 준비 해제로 본다. 신규 입장자는 본인만 미준비.

### 진행 중 방과 입장

- 진행 중 방은 목록에 "진행 중" 태그로 보이되 입장 불가. 관전 없음.
- 게임과 게임 사이(방장이 다음 게임 고르는 동안)에만 새 참가 가능.
- 등반은 스테이지가 이어지는 동안 **한 게임**으로 취급한다.

### 방장 권한

설정, 시작, 다음 게임 선택, 협동의 제안·투표 마감, 협동의 포기, 경쟁에서 끊긴 사람 강제 탈락(§5).

### 강퇴

미확정 (§9).

## 3. 게임 설정

방장이 정하고 매 게임마다 바꿀 수 있다. 결과 화면에 "같은 설정으로 한 판 더" 버튼.

| 설정 | 값 | 구분 |
|---|---|---|
| 종류 | 협동 / 경쟁 | 사용자 결정 |
| 게임 | **단판** / **등반** | 사용자 결정 |
| 시작 길이 | 5~12 또는 랜덤 | 기본값(제안) |
| 시도 횟수 | 4~10, 기본 6 | 기본값(제안) |
| 하드모드 | 켬/끔 | 기본값(제안) |
| 힌트 | 허용 여부 | 사용자 결정 |
| 제한 시간 | 켬/끔, 기본 끔 (2026-11-05 구현에서 기본값을 끔으로) | 켬/끔: 사용자 결정 / 수치: 기본값(제안) |
| 협동 선택 방식 | 투표 / 돌림판 | 사용자 결정 |

### 게임 두 가지만

- **단판**: 한 단어.
- **등반**: 시작 길이에서 12자까지 한 자모씩 올라간다. 12자 완주가 결승선이라 목표 스테이지 수 설정이 없다.
- 개인 모드를 그대로 쓰지 않는다. **연속 클리어**는 난이도 상승이 없어 멀티에서 긴장을 만들지 못해 제외. **데일리 2종**은 모두가 그날 정답을 알게 되므로 제외.

### 제한 시간 (수치는 기본값(제안))

| 게임 | 시간 |
|---|---|
| 등반 | 1스테이지 180초, 스테이지마다 −15초, 하한 60초 |
| 단판 | 라운드 상한 180초 |

만료 = 그 판/스테이지 실패.

### 정답 풀

멀티는 상수 하나 **t=3** (데일리급 깨끗한 풀). 개인용 allowlist인 `POOL_THRESHOLD`와 무관한 별도 상수. D1 `pool` t=3 행은 이미 있으므로 재임포트가 필요 없다.

## 4. 협동 규칙

### 한 행의 흐름: 제안 → 선택 → 판정

1. 각자 자기 입력 행에 단어를 친다 (다른 사람 패널에 실시간 표시). Enter로 제안 확정.
2. 서버가 사전·하드모드를 검사한다. 마감 전까지 수정 가능.
3. 접속 중인 전원이 제안하거나 방장이 "마감"하면 (제안 ≥1) 선택 단계. 같은 단어 제안은 하나로 합친다. **제안이 하나뿐이면 바로 제출.**
4. 선택된 단어가 공유 보드에 들어가고 다음 행 제안으로.

### 선택 방식

| 방식 | 규칙 |
|---|---|
| 투표 | 자기 제안에는 못 찍음. 전원 투표 또는 방장 마감으로 집계. 동률은 돌림판 |
| 돌림판 | 서버가 먼저 결과를 정하고, 클라이언트는 제안 사이를 돌다 멈추는 연출 (약 1.5초) |

2인 방은 사실상 서로의 제안뿐이라 동률 → 돌림판이 된다.

### 그 밖

- 힌트 허용 시 판당 1회, 누구나 사용. 포기는 방장.
- 협동 등반: 공유 보드로 스테이지를 이어가고, 실패 또는 12자 완주로 끝난다.
- 끊긴 사람은 제안·투표 집계에서 뺀다 (탈락 없음).

## 5. 경쟁 규칙

- 같은 정답, 각자 보드, 같은 시도 횟수. 힌트 허용 시 1인 1회. 포기는 본인만 탈락.
- **단판**: 전원이 끝날 때까지 (정답·실패·포기·제한 시간 만료). 순위 = 정답자(시도 수 → 완료 시각) 다음 미정답자(아래 지표).
- **경쟁 등반 = 독립 등반.** 같은 단어 순서를 각자 자기 속도로 오른다.
  - 스테이지 실패는 그 자리에서 등반 종료 (높이 확정).
  - 첫 완주자(12자 클리어)가 나오면 1위 확정 + **유예 60초**. 유예 중 완주하면 완주 순서대로, 유예가 끝나면 나머지를 아래 지표로 고정.
  - 전원 실패해도 종료.

### 순위 지표 (서버 계산)

순서대로 비교한다. 단판은 1번만 빠진다.

| 순서 | 지표 | 정의 |
|---|---|---|
| 1 | 등반 높이 | 클리어한 스테이지 수 |
| 2 | 정답 자모 수 | 현재 스테이지에서 초록으로 확정된 **자리** 수 (행 합집합) |
| 3 | 불완전 정답 자모 수 | 노랑으로 확인된 **자모 종류** 수 |
| 4 | 시도 수 | 적은 쪽이 위 |
| 5 | 공동 | |

### 접속 끊김과 통계

- 이미 끝난 사람은 남은 사람의 진행(색만)과 현재 순위를 본다.
- 접속 끊김 60초 넘으면 자동 탈락 (그래야 "전원 종료"가 성립). 방장은 그 전에도 강제 탈락 가능.
- 멀티 결과는 개인 통계(`stats:<mode>`)에 기록하지 않는다 (기본값(제안)).

## 6. 제한 시간과 무입력

- 서버는 플레이어별(협동은 방별) **마감 시각만** 저장한다. 제출 시 검사하고, 가장 이른 마감에 DO 알람 하나를 건다. 클라이언트는 남은 시간을 받아 카운트다운.
- 무입력 60초(기본값(제안))면 그 사람에게 "진행 중입니다" 경고 모달. 닫고 입력하면 그대로 이어진다. **자동 포기·강제 퇴장 없음.**
- 끝까지 반응 없으면 제한 시간 만료가 실패로 처리한다. 제한 시간을 끈 방에서는 경고만 뜨고 기다린다.

## 7. 아키텍처

### 구조

| 구성 | 역할 |
|---|---|
| `Room` Durable Object (방 하나 = DO 하나) | 정답·참가자·보드·판정 보유. WebSocket Hibernation API, 소켓 첨부에 playerId |
| `Lobby` DO (싱글턴) | 공개 방 목록. 엔드포인트 `/list` `/upsert` `/remove` |

- D1 폴링 대안은 제외했다: "PK 한 행만" 규칙(AGENTS)과 충돌하고 협동 입력 동기화가 안 된다.
- **정답은 DO에만 있다.** 멀티에서는 HMAC 토큰을 쓰지 않는다. `KORDLE_SECRET`과 무관.
- 상태 전송은 변경 때마다 **개인화된 전체 스냅샷** (경쟁은 남의 보드를 색만으로 가공). 방 상태가 작아 (5명 × 10행 × 12자) 패치보다 단순하고 재접속에 강하다.

### 브라우저 저장 최소화와 임시 계정 (사용자 결정 2026-11-01)

신원은 **서버가 발급하는 임시 계정 토큰**으로 한다. 이전 안(sessionStorage `secret` + BroadcastChannel 전달, localStorage `mp-name`)은 폐기했다.

**저장**
- 게임 데이터(추측 행, 초안, 투표, 결과, 상대 정보)는 **브라우저에 저장하지 않는다.** 메모리에만 있고, 새로고침·재접속은 서버 스냅샷으로 전부 다시 그린다. 쿠키는 쓰지 않는다.
- 허용하는 클라이언트 저장은 둘뿐이다. ① localStorage `nkordle:mp-session` 한 키 = `{ token, name, exp }`. ② 현재 방 코드는 URL `?room=CODE`(변경 제안 P6).
- 개인 플레이의 기존 키·형식은 건드리지 않는다. "재촉 소리" 같은 멀티 전용 설정은 저장하지 않고 세션 동안만 유지한다(기본 켬).

**토큰**
- 형식 `mp1.<uid>.<name>.<iat>.<sig>`. `uid`는 16바이트 난수의 base64url(22자), `name`은 닉네임(원문 1~12자, 앞뒤 공백 제거, NFC 정규화)의 base64url, `iat`는 발급 시각(초, 서버), `sig`는 HMAC-SHA256(`KORDLE_SECRET`, `"mp1." + uid + "." + name + "." + iat`)의 base64url 앞 32자.
- 개인 모드 정답 토큰(`n.t.idx`)과 **별개 종류**다. `mp1.` 접두어로 도메인을 나누고, 기존 토큰 형식과 검증 코드는 건드리지 않는다. 서버 저장 없음(무상태), D1·DO 쓰기 없음.
- **만료는 마지막 사용 후 24시간(슬라이딩).** 서버는 `now - iat ≤ 24h`이면 유효로 보고, 유효한 `hello`마다 `iat = now`로 재발급해 첫 `snap`에 `session: { token, exp }`(`exp = iat + 24h`)로 돌려준다. 시각은 서버 기준이고 클라이언트 시계는 믿지 않는다.
- **발급**: 멀티 첫 진입 시 S1에서 닉네임을 입력하면 WS `hello { token?, name }`. 토큰이 없거나 만료·서명 불일치면 서버가 새 `uid`로 발급한다. 서명 불일치도 4005 등으로 거절하지 않고 새로 발급한다(오래된 토큰 때문에 못 들어오는 일을 막기 위해. 만료는 정상 경로). 이름을 바꾸면 같은 `uid`로 새 이름에 서명해 재발급한다. `POST /api/room`(방 생성)도 같은 토큰을 받고, 없으면 발급해 응답에 `session`을 넣는다.
- 클라이언트는 부팅 시 `exp < now`면 키를 지우고 닉네임을 다시 묻는다. 서버가 준 `session`의 `uid`가 바뀌면 키를 덮어쓴다. "나가기"는 세션을 지우지 않는다(24시간 안 재진입은 같은 사람). 설정 모달의 "임시 계정 지우기"는 키를 지우고 S1로 보낸다.

**방 안 신원과 규칙**
- Room DO의 플레이어 키는 `uid`다. 공개 `pid`는 그대로 따로 두고, 스냅샷에는 `uid`·토큰을 절대 넣지 않는다.
- 같은 브라우저의 모든 탭은 localStorage를 공유해 같은 계정이다. 같은 `uid`의 새 소켓이 오면 기존 소켓을 4000으로 닫고 "다른 탭에서 접속했습니다"를 보인다(자리 넘겨받기).
- 끊김 60초 → 탈락 규칙은 유지한다(승부 무결성). 같은 `uid`는 방이 살아 있는 동안 자동 재입장한다: 대기 중이면 자기 자리(준비 상태는 해제), 진행 중이고 60초 안이면 자기 자리로 복귀, 60초가 지나 탈락했으면 관전 없이 결과 화면부터 합류(다음 판부터 참가). 방장 승계는 기존 규칙.
- 기본값(제안): 60초 안의 끊김은 자리를 유지하고 시작을 막지 않는다. 시작 시점에 끊긴 사람이 있으면 방장 화면의 시작 버튼이 "{이름} 내보내고 시작"으로 바뀐다.
- 공용 PC에서 24시간 안에 다른 사람이 같은 자리를 쓸 수 있다. 사내 소수 사용을 전제로 허용한다.

### 개발

- `vite dev`의 `getPlatformProxy`는 같은 워커의 DO를 못 띄울 가능성이 높다. **`pnpm dev`가 깨지면 안 된다.**
- `getPlatformProxy`는 빌드의 프리렌더에서도 돈다(kit `prerender.js`가 어댑터 `emulate()`를 호출). DO 바인딩이 이를 깨뜨리면 `pnpm dev`뿐 아니라 **`pnpm build`와 CI도 깨진다.** wrangler 4.129.1은 같은 워커의 DO 바인딩에 '로컬에서는 동작하지 않는다'는 경고만 찍고 진행하는 것을 코드로 확인했고, workerd도 기동을 거부하지 않았다(2026-11-05 스파이크: build·dev 정상, 경고만 "internal Durable Objects"·"no such Durable Object class is exported").
- 멀티 개발·검증은 `pnpm build && pnpm preview`(wrangler dev)로 한다. 2026-11-05 스파이크: 바인딩이 있어도 dev·build 정상이라 환경 분리는 필요 없다. dev는 WS 불가이고 WS 클라이언트가 붙었다 끊기면 Vite가 `ECONNRESET`으로 죽으므로(DO 무관) 멀티는 preview로만 검증한다.
- DO export는 빌드 후처리가 붙인다. `pnpm build` = `vite build && node scripts/postbuild-do.mjs`가 `_worker.js` 끝에 한 줄(멱등)을 더한다: `export { Room, Lobby } from "../../src/lib/server/mp/index.ts";`. 경로는 barrel `index.ts`(Room·Lobby 재export)를 거치고 `.ts` 확장자를 포함한다. `wrangler deploy --dry-run` 종료 0, 번들 `$lib/` 0 (2026-11-05 스파이크).
